### 4.1 근본 원인 분석 (I-004 — 로그인 실패 · **해소됨 §1.6**)

| 단계 | 측정값 / 근거 |
|------|--------------|
| 증상 | `signup` → 201(userId 발급), 곧바로 동일 `phone`/`password`로 `login` → 401 `전화번호 또는 비밀번호가 올바르지 않습니다` (재현 100%) |
| 절반 분리 | **중복 가입 시 409** = `login`과 동일한 `.eq('phone_hash', …).maybeSingle()` 조회가 **사용자를 찾음** → 401 원인은 "사용자 없음"이 아니라 **비밀번호 비교 실패** |
| 스키마 | `users.phone_enc` = **`BYTEA NOT NULL`** ([001_initial_schema.sql:9](../src/backend/migrations/001_initial_schema.sql#L9)) · **비밀번호 전용 컬럼 부재** |
| 코드 | `signup`은 `phone_enc: passwordHash`(bcrypt 문자열)를 BYTEA에 저장([signup/route.ts:45](../src/frontend/app/api/auth/signup/route.ts#L45)). `login`은 `bcrypt.compare(password, user.phone_enc)`([login/route.ts:36](../src/frontend/app/api/auth/login/route.ts#L36)) |
| 결론 | bcrypt 해시(`$2a$…` 60자 문자열)가 **BYTEA 컬럼을 거치며 hex(`\x2432…`)로 변형**되어 되읽힘 → `bcrypt.compare`가 항상 false → 401. **모든 신규 가입자가 로그인 불가** |
